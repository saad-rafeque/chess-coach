# Chess Coach 1.1.3 audit and handoff — 13 November 2026

## Scope and decisions

Baseline: `b679d55` / released version 1.1.0. The owner resumed the previously
paused audit, requested a quieter, more engaging Home, and an update for Android,
Linux and Windows. Later instructions explicitly removed PiP and prioritized
split-screen, and asked us to avoid redundant test runs. PiP is removed from
the Android manifest, native activity, Dart bridge, menus and layout branches.
Android remains resizable; split-screen and its compact Coach/Hint controls stay.

Original Light, Dark and Wooden themes, additional Midnight/Amethyst/Sand,
Glass/Fluent/Material interface styles, boards and piece sets remain available.
Home now emphasizes Play, Puzzle break and the next lesson. Session planning,
coach tips, skills and recent games remain in expandable sections; due review
cards and unfinished sessions remain immediately accessible.

## Confirmed findings and fixes

| ID | Reproduction / impact | Resolution and evidence |
|---|---|---|
| RULE-01 | An uncapturable en-passant target prevented recognizing the third occurrence of the same legal position. | Repetition uses legal en-passant rights; uncapturable and genuinely capturable cases covered. |
| DAY-02 | Subtracting 24 hours from local midnight dropped valid streaks across daylight-saving changes. | Calendar-day arithmetic in puzzle and overall streaks; spring/fall regression under `TZ=America/New_York`. |
| REVIEW-03 | A syntactically valid synced review with an illegal best move created an impossible study puzzle. | Reject illegal suggestions when constructing the review; regression added. |
| AUTH-04 | Sign-out/account switch while the keychain was locked could resurrect its previous account after unlocking. | Authoritative private fallback/tombstone, migrated once the keychain works; both cases reproduced and tested. |
| SYNC-06 | HTTP 401 repeatedly reused the rejected token. | Invalidate access cache, retry once with fresh authorization, then offer Connect if rejected again. |
| SYNC-07 | Offline followed by expired authorization still displayed “No connection”, hiding the reconnect action. | Independent review finding: definite auth/Drive responses clear the stale offline flag; regression included. |
| UPDATE-03 | A checksum-fetch failure incorrectly throttled automatic update checks for four hours. | Record successful check time only after complete metadata retrieval. |
| LINUX-01 | A new AppImage icon was ignored if its bytes had the old icon's length. | Compare file contents, with a same-length replacement regression. |
| UI-06 | Lessons progress pill and row metadata overflowed at 240 px / 200% text. | Header stacks trailing information, narrow rows place metadata below the title. |
| UI-07 | A long coach name overflowed the desktop panel at 200% text. | Bounded coach title with ellipsis. |
| UI-08 | New-game heading/options overflowed a 700×320 window at 200% text. | Scroll heading/options together; keep actions accessible and allow toggle text to flex. |
| UI-09 | Expanded Home skills/recent-game metadata overflowed at 240 px / 200% text. | Wrapping metadata and review rows; narrow/desktop Home regression matrix. |
| UI-10 | Physical phone showed the evaluation number clipped against the board in a 14 px slot. | Evaluation slot follows text scaling and includes padding; affected layout/theme checks run for this change; a notched-phone inset regression caught insufficient header space and was corrected. |
| RELEASE-01 | Publication previously preceded reproducibility results and did not depend on the security scan. | Release now depends on security and all three independent rebuilds; comparisons use original CI artifacts before publication. |
| RELEASE-02 | APK comparison used CRCs and displayed certificates without explicitly comparing them. | SHA-256 of every ZIP payload, reject duplicate entries, verify both APK signatures and compare certificate SHA-256 digests. |
| RELEASE-03 | The first v1.1.1 tag run stopped before publication because only `AssetManifest.bin` differed between Android builds. Flutter 3.47.7 sorts asset keys but discovers 2x/3x image variants in filesystem order. | `tool/prepare_flutter.py` sorts variant files before manifest generation, preserves base-image-first behavior, and invalidates the compiled Flutter tool. All CI build environments apply the same guarded patch. Unknown SDK code fails closed; exact payload and signing checks remain unchanged. |

updates must keep its signing identity and app data. No uninstall or data clear
is authorized or needed. Local Android test builds use the repository's Android

and corrected after this inspection. The first streamed ADB install failed its

1080×1188 bounds. The board, navigation and bold Hint fit; first Hint highlighted
f1, second returned Bc4, and the full Coach panel opened. No move was made.

by mocked authorization tests. Windows CI tests/builds do not replace manual
interaction on a Windows user's GPU/display. No finite audit proves that no
possible bug remains.
